## 0. Purpose

This is the authoritative shared contract for the v0.3 speech-translation wave. It freezes
what must remain true across implementation boundaries: the audio capture boundary, the
trusted-context ownership, the permission model, the chat/speech configuration split, the
message/data contracts, lifecycle and restart behavior, privacy and retention invariants,
error/fallback semantics, latency/cost boundaries, the testing strategy, and explicit
non-goals. Child Issues narrow the work to satisfy this Spec but must not silently change it.

Source-of-truth precedence (per repository SDD policy):
`repository rules → this Spec → Issue scope + acceptance criteria → existing implementation → agent assumptions`

If an implementer finds a conflict with this Spec or with latest `main`, they stop and report
`SPEC BLOCKER` with the smallest conflicting decision. They never silently rewrite the contract
inside a child PR.

## 1. Overview

Twitch 實況主語音 → (capture) → (transcription + translation) → (subtitle overlay on the video player).
Chat translation continues to work unchanged and independently. Speech is a separate pipeline with
a separate provider configuration, separate API-key namespace, separate diagnostics, and separate
cost/quota accounting.

Chosen capture path (frozen, per research):

```
user gesture (popup enable + consent)
  → SW: chrome.tabCapture.getMediaStreamId({ targetTabId })     [Chrome 116+]
  → SW: ensure offscreen document (reasons: ['USER_MEDIA'])     [max 1]
  → offscreen: getUserMedia({ audio: { chromeMediaSource: 'tab', chromeMediaSourceId } })
  → offscreen: AudioContext (connected to destination so the viewer still hears Twitch)
  → offscreen: AudioWorklet downsample → 16 kHz mono PCM (little-endian) chunks
  → offscreen → SW: chrome.runtime Port (long-lived) delivers {chunkId, pcm, startMs, endMs}
  → SW: Gemini chunked transcription+translation (generateContent, inlineData base64)
  → SW: broadcasts speech_state / speech_caption to the Content Script
  → Content Script: renders subtitle overlay (vanilla DOM + shadow root)
```

Content-script Web Audio (`createMediaElementSource`/`captureStream`) is REJECTED because Twitch HLS
media is cross-origin and Web Audio taint yields silence, and it interferes with Twitch's own player
audio graph. All capture happens in the offscreen document via `tabCapture`.

## 2. Audio capture boundary

- Audio is captured **only** from the active Twitch tab, **only** after an explicit user gesture
  (popup enable + consent). Never on `onInstalled`, extension startup, or tab load.
- The `tabCapture` MediaStream is consumed **only** in the offscreen document. Never in the content
  script (known mute-unrecoverable bug), never in the SW (no media APIs).
- Capture produces **16 kHz mono 16-bit little-endian PCM**, in bounded chunks (~200–500 ms each).
  Chunk payloads must fit well under the MV3 message-size limit (~32 MB); 500 ms of 16 kHz mono is
  ~16 KB.
- VAD/silence gating is in scope for the pipeline: silent segments are not sent to the provider and
  do not consume budget. A minimal "no speech" gate may be a fixed silence threshold; quality gates
  (speech vs music discrimination) are deferred.
- Tab mute: `tabCapture` mutes the captured tab to the user by default. The offscreen document must
  connect the captured stream to its AudioContext destination so the viewer continues to hear Twitch.
  This is a hard requirement (non-negotiable UX).
- Stream is `stop()`-ed on: user disable, SW context invalidation, tab close/navigation off Twitch,
  capture error, daily/session budget exhaustion.

## 3. Trusted-context ownership

- **API keys** (full) live only in `chrome.storage.local`, readable only by the Service Worker,
  exactly as today (`getApiKeyForServiceWorker`, settings.ts). Content Script and Popup never see
  full keys.
- The offscreen document can access **only `chrome.runtime`** (offscreen restriction): it cannot read
  `chrome.storage` and therefore can never read keys. **All provider calls (transcription +
  translation) are made by the Service Worker.** The offscreen document only captures and forwards PCM
  chunks; it never holds or sees an API key. This is the key-exposure invariant.
- The Service Worker owns: capture lifecycle, offscreen lifecycle, provider calls, cost/quota
  accounting, error sanitization, and state broadcast.
- The Content Script owns: overlay DOM, subtitle rendering, and the display mirror of `speech_state`.
  It sends only `speech_control {action}` messages and never reads storage.

## 4. Permission model (manifest delta)

```jsonc
{
  "manifest_version": 3,
  "minimum_chrome_version": "116",
  "permissions": [
    "storage",
    "tabCapture",
    "offscreen",
    "activeTab"          // required by tabCapture for the target tab
  ],
  "host_permissions": [  /* NO NEW host entries required for capture */
    "https://*.twitch.tv/*",
    "https://generativelanguage.googleapis.com/*",
    "https://api.deepseek.com/*",
    "https://api.openai.com/*",
    "https://api.anthropic.com/*"
  ]
}
```

- `tabs` permission is **not** required: the SW resolves the active Twitch tab via
  `chrome.tabs.query({ active: true, lastFocusedWindow: true })` under the existing
  `*.twitch.tv` host permission.
- `activeTab` is required for `tabCapture` to authorize the target tab.
- Adding `tabCapture` triggers the CWS warning "Read and change all your data on all websites";
  the extension store listing must explain that capture is gesture-gated, subtitle-only, and never
  persisted. This is accepted.
- No microphone permission is added: capture is tab audio, not user mic. (Mic capture is a
  non-goal.)

## 5. Chat/Speech provider configuration split

- `UserSettings` (storage-facing, flat, `chrome.storage.local` key `userSettings`) gains **one
  nested field** `speechConfig: SpeechTranslationConfig` with defaults and a
  `normalizeSpeechConfig` guard, exactly mirroring the existing `geminiQuota`/`chineseVariantMode`
  pattern. No storage migration is required: the existing `{...DEFAULT_SETTINGS, ...stored}`
  merge supplies defaults for missing fields.
- New types in `src/providers/speech-types.ts`:

```ts
export const SPEECH_PROVIDER_IDS = ['gemini'] as const
export type SpeechProviderId = (typeof SPEECH_PROVIDER_IDS)[number]

export interface SpeechTranslationConfig {
  speechEnabled: boolean                 // default false
  speechProvider: SpeechProviderId       // 'gemini'
  speechModel: string                    // default GEMINI speech model
  speechTargetLanguage: string           // independent of chat targetLanguage
  captionMaxLines: number                // default 2
  captionOpacity: number                 // 0..100, default 100
  maxSessionMinutes: number              // hard per-session cap, default 30
}
```

- **Independence contract (must hold):** changing `speechConfig` must not change chat behavior and
  vice versa. Chat continues to use `selectedProvider`/`selectedModel`/`targetLanguage`. Speech uses
  only `speechConfig` fields.
- **API-key namespace:** new `speechProviderApiKeys` + `speechProviderApiKeyPreviews` storage keys
  (keyed by `SpeechProviderId`), plus `saveSpeechApiKey`/`deleteSpeechApiKey`/
  `getSpeechApiKeyForServiceWorker`/`getMaskedSpeechApiKeyForPopup` mirroring the existing key
  functions. Speech never reads `providerApiKeys`. This keeps the Gemini+Gemini case (chat and
  speech both on Gemini) independent: rotating the chat Gemini key does not affect speech.
- **Provider interface:** a new `SpeechProvider` interface (in `src/providers/speech-types.ts`),
  NOT an overload of `TranslationProvider`:

```ts
export interface AudioChunk {
  chunkId: string
  data: ArrayBuffer            // 16 kHz mono 16-bit PCM
  mimeType: string             // 'audio/pcm;rate=16000'
  startMs?: number
  endMs?: number
  isFinal?: boolean
}

export interface SpeechTranslationResult {
  id: string
  text: string                 // transcribed source-language text (interim or final)
  translatedText?: string      // present only on final
  startMs?: number
  endMs?: number
  isFinal?: boolean
  error?: ProviderError        // reuse the ProviderError union from shared/messages.ts
}

export interface SpeechProvider {
  readonly id: SpeechProviderId
  readonly displayName: string
  readonly models: readonly ProviderModel[]
  readonly defaultModel: string
  transcribeChunk(chunk: AudioChunk, apiKey: string, model: string,
                  targetLang: string, signal?: AbortSignal): Promise<SpeechTranslationResult[]>
  validateKey(apiKey: string): Promise<KeyValidationResult>
}
```

  `transcribeChunk` is a **non-live, bounded-window, request-per-chunk** call (chunked
  `generateContent` with `inlineData`). This bounds cost (a request per ~5–10 s window, cacheable)
  and fits MV3 lifecycle (no long-lived WebSocket to keep alive). Live WebSocket API is **deferred**
  to a later wave (unbounded context re-billing on an always-on stream).
- A `speech-registry.ts` mirrors `registry.ts` with `getSpeechProvider(id)`,
  `listSpeechProviderMetadata()`, and `isAllowedSpeechProviderEndpoint` (Gemini endpoint already in
  host_permissions).
- Reused as-is from chat: `ProviderError`, `KeyValidationResult`, `ProviderModel`, `RateLimiter`
  (keyed `'gemini-speech'`), `parseRetryAfterMs`/backoff. `CharacterTokenEstimator` and
  `QuotaScheduler` are **not** reused (speech is not token-batch-scheduled).
- The dead `src/providers/adapters/` directory is out of scope for this wave (separate cleanup).

## 6. Message/data contracts

New message types appended to `MessageType` and `MESSAGE_TYPES` in `src/shared/messages.ts`, each
with a type guard in the existing style, tested in `src/shared/messages.test.ts`:

```
speech_control            CS → SW   { action: 'start' | 'stop' | 'toggle'; channelName?: string }
speech_state              SW → CS   { state: 'idle' | 'consent_pending' | 'capturing' | 'transcribing'
                                      | 'paused' | 'error'; reason?: SpeechErrorReason; errorKey?: string }
speech_caption            SW → CS   { id: string; text: string; interim: boolean; lang?: string }
speech_caption_cleared    SW → CS   { reason: 'idle' | 'silence' | 'disabled' }
speech_settings_updated   SW → CS   Partial<SpeechTranslationConfig>-compatible broadcast payload
```

- `speech_state` and `speech_caption` payloads **never carry** API keys, raw audio, or channel names.
  The caption `text` is the display text — for final captions the translated output, for interim
  captions (which are shown untranslated, see §10) the source-language caption draft. Display text
  is the feature's output and is allowed by design; it must never enter storage, diagnostics, or
  error payloads (§8.4, §11 privacy assertions exclude the display-text field). Error payloads carry
  only a fixed i18n message key (`errorKey`) — exact sanitization precedent is
  `sanitizeTranslationResultForContent` (message-router.ts). `SpeechErrorReason` is one of
  `'auth' | 'rate_limited' | 'quota_exceeded' | 'network' | 'no_twitch_tab' | 'permission_denied'
  | 'context_invalidated' | 'budget_exhausted' | 'unknown'`.
- `SettingsUpdatePayload` is additive (its guard only checks "is an object") — no change needed,
  but speech settings changes broadcast via `speech_settings_updated`.
- New diagnostics: `DiagnosticStage` and `DIAGNOSTIC_STAGES` gain `speech_*` counter stages
  (`speech_started`, `speech_stopped`, `speech_caption_emitted`, `speech_chunk_sent`,
  `speech_error`). All carry only counters/timestamps — never transcript text, audio, or keys.
  Popup's `DIAGNOSTIC_LABELS` gains matching labels.

## 7. Lifecycle and restart behavior

- Capture lifecycle is owned by the SW. On `speech_control start`: ensure consent, create offscreen
  doc, `getMediaStreamId`, hand streamId to offscreen, offscreen opens `getUserMedia`, starts PCM
  stream, opens the runtime Port to the SW. On `stop`: close Port, `track.stop()`, close offscreen
  doc, clear badge.
- The offscreen document (reason `USER_MEDIA`) has no 30 s auto-close (only `AUDIO_PLAYBACK` does);
  it stays alive while the stream is active. Recreate on demand via `chrome.runtime.getContexts()`
  (Chrome 116+).
- **SW suspension:** when the SW idles (≈30 s) and is terminated, the open Port drops and the
  offscreen document detects `onDisconnect`, **stops the stream** (privacy invariant), and clears
  its buffer. Nothing keeps a suspended SW alive — an open Port does not prevent termination — and
  the stream never outlives the SW that authorized it. On the next SW wake, it restores minimal
  state from `chrome.storage.session` (speech session UUID, running audio-seconds, budget counters)
  and reports a reconnectable state; the user re-enables to resume, which recreates the offscreen
  doc and re-runs `getMediaStreamId` (single-use). The reason there is no keepalive problem is that
  no long-lived WebSocket is used; a speech session therefore does not depend on keeping the SW
  alive, it simply pauses on SW termination.
- **Extension context invalidation is terminal** (existing invariant). On invalidation the overlay is
  removed and no capture is resumed.
- **Tab lifecycle:** on tab navigation away from a Twitch channel or tab close, the SW detects it,
  stops capture, and returns to `idle`. A VOD/Clip page is a non-goal for v0.3 (see §13).

## 8. Privacy and retention invariants

1. **Raw audio never persists.** PCM chunks live in memory only (offscreen buffer + in-flight
   Port message), are dropped immediately after forwarding, and are cleared on stop/error/worker
   end. No raw audio is ever written to `chrome.storage.local`/`session`, IndexedDB, or disk.
   There are **no exceptions in v0.3**; any future raw-audio persistence requires a new Spec +
   explicit user opt-in + retention cap + deletion path + `PRIVACY_POLICY.md` update.
2. **Consent is two-stage.** (a) Install/store stage: the `tabCapture` CWS warning plus the store
   listing explaining capture purpose. (b) Runtime stage: popup "語音字幕" toggle (default OFF);
   first enable shows a consent panel stating: capture current Twitch tab audio, send to the chosen
   BYOK provider for transcription, audio is never stored, usage is billed per your key, and capture
   is active-visible. The user's click is the gesture that authorizes `getMediaStreamId`.
3. **Capture is persistently visible.** While active: `chrome.action.setBadgeText('REC')` + red
   badge + recording-state icon + tooltip; cleared on stop. Combined with Chrome's built-in tab
   capture indicator.
4. **Transcript/translated captions are UI-transient.** The content script keeps only the last
   `captionMaxLines` rendered cues in memory; nothing is persisted. Transcript text never enters
   diagnostics, error messages, or storage.
5. **Non-content metadata only.** Allowed in memory: chunk sequence, timestamps, chunk duration ms,
   session UUID (random, not channel-derived), cumulative captured-seconds (for budget accounting).
   Forbidden: transcript text, audio, channel-name↔audio association.
6. **Keys stay in the SW.** Offscreen and content never hold keys (see §3).

## 9. Error/fallback semantics

| Failure | Behavior |
|---|---|
| `auth` | Stop capture immediately, `track.stop()`, badge → error state, popup shows generic error (fixed key), **no auto-retry**; user must re-enable. |
| `rate_limited` / `quota_exceeded` | Pause transcription, keep bounded capture buffer (≤10 s), surface "字幕暫停（用量限制）", resume on cooldown/retry-after (`RateLimiter` keyed `'gemini-speech'`). No blind retransmit of failed chunks. |
| `network` drop mid-stream | In-flight chunk marked failed and dropped; each chunk is sent **at most once** (no retransmit cost). After a threshold of consecutive failures, stop capture and require re-enable. |
| `no_twitch_tab` | Return to `idle`; no capture attempted. |
| `permission_denied` (tabCapture/getUserMedia failure) | Surface error state with `permission_denied`; guidance in popup; no retry loop. |
| `budget_exhausted` | Stop capture at session or daily cap; popup shows usage; user may raise budget or wait for daily reset. |
| SW suspension / Port drop | Offscreen stops the stream (privacy), SW restores session state on wake; reconnectable. |
| Context invalidation | Terminal; overlay removed; no resume. |

Every error surfaced to the user carries only a fixed i18n key — never raw provider messages, keys,
audio, or transcript.

## 10. Latency and cost boundaries

- **Targets (MVP):** capture→interim caption < 1.5 s; capture→translated final < 3 s.
- **Interim policy:** interim captions are shown untranslated (reduced opacity); only the final
  caption is translated. This bounds translation cost to one per utterance, not per STT update.
- **Chunk cadence:** 200–500 ms PCM chunks sent to SW; transcription requests per ~5–10 s window
  with overlap; silence gaps skipped (VAD gate).
- **Cost model (frozen):** chunked Gemini `generateContent` (non-live) — bounded per-minute audio
  cost (~$0.001/min class), no long-lived session context. The Live WebSocket API is **rejected
  for v0.3** because it re-bills full context per turn and is unbounded on an always-on stream.
- **Budget controls (frozen):** default OFF; `maxSessionMinutes` (default 30) hard stop per session;
  a daily audio-minute cap (persisted to `chrome.storage.local`, mirrored to session) with
  provider-day rollover; quota/backoff reuse keyed `'gemini-speech'`. Popup shows cumulative
  captured minutes and an estimate.
- Speech cost/quota accounting is separate from chat quota buckets; it never consumes chat Gemini
  RPM/TPM/RPD.

## 11. Testing strategy

- **Determinism:** no test touches `tabCapture`, `MediaRecorder`, `getUserMedia`, or a live
  provider. A `SpeechSource` interface is injected so tests feed scripted PCM/transcript events.
- **Unit (Vitest, colocated):**
  - `src/shared/speech-state.test.ts` — pure reducer transitions (idle→consent_pending→capturing→
    transcribing→error→recovery; pause/mute; budget stop; terminal invalidation).
  - `src/shared/messages.test.ts` (extend) — guards for the new speech messages; reject malformed;
    privacy assertion (no key/raw-audio/channel shapes; the `speech_caption.text` display-text
    field is the feature output and is exempt per §6).
  - `src/storage/settings.test.ts` (extend) — `speechConfig` defaults/normalization; backward
    compat with legacy stored settings.
  - `src/background/speech-pipeline.test.ts` — pipeline with fake source + mock speech provider +
    mock translator: scripted chunks → translated captions under fake time; dedup; error→recovery;
    privacy (no keys/raw audio/channel names in `speech_state`; `speech_caption.text` is the
    display-text output and is exempt per §6).
  - `src/content/subtitle-overlay.test.ts` — jsdom: idempotent host mount, shadow-root structure,
    interim/final styling, max-lines rolling, dirty-check no-op, destroy on idle/invalidation.
  - `src/content/twitch-selectors.test.ts` (extend) — `VIDEO_PLAYER` + fallbacks merge/dedupe.
- **E2E (Playwright, no live provider):** push `speech_caption`/`speech_state` from the SW context
  into the real content script via `chrome.tabs.sendMessage` (already the pattern at
  service-worker.ts:267); assert overlay renders, interim→final flips, error chip shows the
  sanitized key and auto-hides, overlay removed on `idle`. Provider HTTP is routed/aborted.
- **Validation gates before any PR:** `pnpm check:agent-docs`, `pnpm lint`, `pnpm typecheck`,
  `pnpm test`, `pnpm build`, then foreground review and adversarial review against the exact-head
  Issue + this Spec. Speech settings/selectors/copy must be threaded through the exhaustive
  `MessageKey`/`MESSAGE_KEYS`/`FALLBACK_MESSAGES` i18n and `_locales` bundles.

## 12. Parallelization boundaries

The Spec deliberately carves disjoint file ownership so Issues can be implemented in parallel:

- **Settings split** — `src/storage/settings.ts`, `src/providers/speech-types.ts` (config + key
  functions), `src/shared/messages.ts` (types/guards only as needed for settings broadcast),
  `src/popup` (settings section), `src/shared/i18n.ts`.
- **Capture primitive** — `manifest.json` (permissions only), new `src/offscreen/` document,
  new `src/background/speech-capture.ts`, `src/background/service-worker.ts` (capture wiring),
  `src/content/twitch-selectors.ts` (video-player selector).
- **Gemini speech adapter** — `src/providers/speech-types.ts` (interface), new
  `src/providers/speech-gemini.ts`, new `src/providers/speech-registry.ts`. Depends on the
  interface from the settings split.
- **Speech pipeline / SW orchestration** — `src/background/speech-pipeline.ts`,
  `src/background/speech-state.ts` (shared reducer), `src/background/speech-budget.ts`,
  `src/background/service-worker.ts` (orchestration), `src/shared/messages.ts` (speech messages).
  Depends on capture primitive + adapter.
- **Subtitle overlay** — `src/content/subtitle-overlay.ts`, `src/content/twitch-entry.ts` (wiring),
  `src/content/twitch-selectors.ts` (overlay anchor), E2E spec. Depends on the message contracts
  only.
- **Popup controls + consent** — `src/popup/App.tsx`, `src/shared/i18n.ts`, `src/shared/messages.ts`
  (consent copy). Depends on settings split.
- **Tests/E2E** — colocated test files + new `e2e/speech-subtitles.spec.ts`; a shared test helper
  `src/test-utils/fake-speech-source.ts`. Cross-cutting but file-disjoint.

Disjoint ownership is a goal, not a guarantee: two Issues that touch `src/shared/messages.ts` or
`src/background/service-worker.ts` are **not** parallel-safe unless each touches only its own
message types / call sites and the Spec freezes the contract. The Spec author (controller) assigns
the concrete Issue graph in Phase 3 and dispatches only disjoint ones in parallel.

## 13. Explicit non-goals (v0.3)

- Live WebSocket Gemini API and any speech-to-speech output (Gemini 3.5 Live Translate).
- VOD / Clip subtitle support (channel live pages only).
- Microphone (viewer) capture.
- Raw audio persistence, transcripts, or any audio in storage.
- Per-channel speech settings overrides (speech config is global-only in v0.3; per-channel
  chat settings keep working). Draggable overlay, timestamps, transcript mode, caption styling
  presets, multi-provider speech beyond Gemini.
- Refactoring/deleting `src/providers/adapters/`.
- Reusing chat `Translator`/`QuotaScheduler`/cache for speech audio (caption translation reuses
  the translator for final text only if already present; a dedicated speech translation call inside
  the speech provider is acceptable and preferred to keep the speech pipeline self-contained).
- Changing the chat pipeline, `TranslationProvider`, `ProviderId`, or chat message types.
- Adding any non-Gemini speech provider or a speech fallback provider chain.

## 14. Recorded decisions / unresolved questions

Decisions (frozen, evidence-backed):
1. Capture = `tabCapture` + offscreen (`USER_MEDIA`) + AudioWorklet PCM. Content-script WebAudio
   rejected (CORS taint + Twitch player interference).
2. Provider calls stay in the SW (offscreen has no `chrome.storage`, only `chrome.runtime` — a
   natural key boundary). Offscreen never holds keys.
3. Speech uses a separate config, separate key namespace, separate diagnostics, separate quota —
   chat/speech independence is a hard contract.
4. Gemini chunked `generateContent` (non-live) for v0.3; Live API deferred (cost).
5. Tab audio keeps playing to the viewer (offscreen destination connection) — mandatory UX.
6. Consent = popup toggle (default OFF) + first-enable consent panel (gesture) + persistent
   `REC` badge.
7. Testing is fully deterministic via a `SpeechSource` injection point.

Smallest unresolved decisions (recorded, do not block the shared Spec; block only the owning Issue):
- **D1 (capture Issue):** exact `getMediaStreamId` gesture context — SW vs popup-originated call.
  Research says the gesture must originate from a user action; Chrome requires an invocation
  window. The capture Issue must PoC both and freeze the call site. Until then the Spec allows
  either (both are inside the extension and gesture-gated).
- **D2 (adapter Issue):** exact Gemini audio input support surface for the chosen model — whether
  `inlineData` `audio/pcm;rate=16000` is accepted by the frozen model directly, or whether PCM must
  be wrapped (e.g., WAV/`audio/wav` container). The adapter Issue owns the format normalization
  decision; the Spec only requires 16 kHz mono PCM as the internal capture format.
- **D3 (adapter Issue):** interim-vs-final granularity of chunked `generateContent` — whether to
  emit interim captions from partial windows or only finals. The Spec fixes the UX contract
  (interim untranslated ≤1.5 s, final translated ≤3 s); the adapter chooses the mechanism.
- **D4 (budget/pipeline Issue):** whether the daily audio-minute cap persists via a new key or
  rides the existing `geminiQuota` daily rollover machinery. Spec requires: persisted daily cap,
  separate from chat quota. Owner picks the mechanism.

No remaining decision requires escalation to a stronger reasoning model: the frozen choices are
directly evidenced by the research reports, and the four recorded items are bounded implementation
details owned by single Issues.
